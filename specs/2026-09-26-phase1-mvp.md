# 规格：orgos MVP 阶段一——人与代理组的即时通讯

## 背景与目标

orgos 是一个 AI 原生办公软件的实验。核心假设：每个员工配一组 AI agent（下称"代理组"），人和代理都是一等主体，信息默认先经过代理再到人。阶段一只验证四种沟通能不能在同一个即时通讯里跑通，外加让代理通过员工自己的电脑执行操作：

| 编号 | 沟通 | 验证的价值 |
|---|---|---|
| C1 | 我和自己的代理组聊 | AI 提效 |
| C2 | 我和其他真人聊 | 传统办公不退化 |
| C3 | 别人和我的代理组聊，超出授权的问题转给我本人 | 不开会也能拿到信息、推进决策 |
| C4 | 别人的代理和我的代理自动协商，结果交给双方本人确认 | 全自动沟通与决策 |
| R | 把自己的电脑配对成"设备 Runner"，我的代理能在上面读写文件、执行命令（有风险的先问我） | 虚拟总线的第一个节点 |

**成功标准**：`bun scripts/e2e.ts` 在无网络、`MOCK_LLM=1` 下退出码 0，覆盖 C1–C4、R 与租户隔离；接真 DeepSeek 时 `bun scripts/smoke-llm.ts` 跑通 C1 与 C3 各一轮；Web 界面上三个测试账号能手工走完全部场景。

## 非目标

- 手机端、推送、音视频、文件附件、消息编辑与撤回、已读回执、搜索界面。
- 端到端加密（本产品的组织记忆在服务端，明确不做）。
- 一个人属于多个租户（数据模型留好租户编号，但阶段一一个用户只属于一个租户）。
- 设备 Runner 上的插件、MCP、浏览器、算力共享；手机做 Runner。
- 多模型供应商切换（只接 DeepSeek，但供应商配置结构照 wisp 保留，便于后加）。
- 生成式界面、组织记忆图谱、审批引擎、定时任务。
- 生产部署、HTTPS、限流。

## 假设（施工前需用户扫一眼）

1. **代理组的默认构成**：每个成员注册后自动得到两个代理——`幕僚长`（`role=front`，对外代表本人、负责分派，不可删除）和 `执行助理`（`role=specialist`，默认用于绑定设备 Runner）。本人可以再建、改、删专员。
2. **别人找我的代理组，入口统一是我的幕僚长**；幕僚长可以把事转给我组里的专员。别人不能直接私聊我的专员。
3. **代理替别人办事时能看到什么**：只能检索本人标为"共享"的资料和记忆；本人的私聊、私有记忆、设备能力一律不可用。设备工具只在代理为本人办事时开放。
4. **协商（C4）的结构**：代理之间不发自由聊天，每一步必须调用 `negotiation_reply` 工具，带 `status`（continue/agree/reject/need_owner）和可选的 JSON `proposal`；对方用 `agree` 回应同一个 proposal（深度相等）即达成。最多 8 步。
5. **群聊里多个代理的发言规则**照 Lorca：被 @ 的先说，其余按入群顺序各轮到一次，可以无声跳过；有人发言才进下一轮，只点听到新内容的代理；最多 4 轮；人发新消息会结束当前这一轮。
6. **一个用户只属于一个租户**；注册时要么新建组织，要么用邀请码加入。
7. **代理引擎自己写一个最小循环**，不用 pi（理由见 `decisions/0001-agent-loop.md`，施工第一步写入）。

### 数据模型

事件类型（`packages/protocol/src/events.ts`，每种都有 Zod 载荷）：

| type | payload | 说明 |
|---|---|---|
| `message.posted` | `{ text, mentions: string[] }` | 人或代理的消息；代理消息 `onBehalfOfId` = 代理所属的人 |
| `agent.action` | `{ tool, summary, ok }` | 代理调用了一个工具（界面折叠显示，便于审计） |
| `escalation.created` | `{ workItemId, question }` | 已转给本人 |
| `escalation.resolved` | `{ workItemId, action, text? }` | 本人答复或拒绝 |
| `negotiation.step` | `{ step, status, message, proposal? }` | 协商的一步 |
| `negotiation.ended` | `{ outcome: 'agreed'\|'rejected'\|'exhausted', proposal? }` | 协商结束 |
| `confirmation.resolved` | `{ workItemId, action: 'confirm'\|'reject' }` | 本人确认或驳回协商结果 |
| `member.joined` | `{ principalId }` | 入群 |

`work_items.payload`：`decision` 由 escalate 产生 `{ question, askedById }`；`approval` 由设备工具产生 `{ runnerId, capability, args }`；`confirmation` 由协商产生 `{ negotiationConversationId, proposal }`；`commitment` 由 `create_commitment` 产生 `{ }`。

### 代理引擎（`apps/server/src/agent/`）

**LLM 客户端**（`llm.ts`）：OpenAI 兼容 Chat Completions，`stream: true`，`stream_options.include_usage`，对 DeepSeek 带 `thinking: { type: 'disabled' }`（该模型下有效，不带时思考会吃光 `max_tokens`），`max_tokens: 4000`，经 `normalizeOpenAiRoles`。每次调用结束（成功、失败、中止）都写一行 `llm_requests`；**写账失败只记日志，绝不影响回复**。`MOCK_LLM=1` 时换成 `mock-llm.ts`（见下），不出网。密钥来自 `DEEPSEEK_API_KEY`；Runner 永远拿不到任何 LLM 密钥。

**运行循环**（`loop.ts`，目标 ≤300 行）：输入 = 代理、触发事件、会话、行事对象（`actingFor`：本人或他人）；组装系统提示 + 最近 40 条会话事件（转成 user/assistant 消息，代理自己的消息为 assistant，其余带 `【显示名】` 前缀为 user）→ 调模型 → 若有工具调用则执行并追加结果，继续 → 无工具调用时把文本作为 `message.posted` 落库。单次运行最多 8 次模型调用，超出则落一条"这件事步骤太多，我先停在这里"的消息并结束。流式文本经 `draft` 帧推送；落库后推 `event` 帧。

**调度**（`scheduler.ts`）：同一会话同一时刻只有一轮在跑；新的人类消息到来时，正在跑的代理完成当前这一步（模型调用或工具）后停止，然后从新消息开始新一轮。`POST /stop` 立即中止（`AbortController`）。

**谁该回应**：
- `dm`（一人一代理）：代理总是回应。
- `group` 与含多个代理的会话：按假设 5 的轮次规则；轮到时代理可调用 `pass` 工具无声跳过。
- 代理自己发的消息不触发其他代理，只有轮次规则和 `delegate_to_teammate`、协商能让代理之间传话。
- observer（如 C3 里的本人）在会话里插话不触发代理运行；这些话作为上下文出现在代理下一次运行里。
- 防循环：同一会话里没有新的人类消息时，代理之间的交接累计 ≥8 次就停止。因任何上限停止（轮次 4、交接 8、单次运行 8 次模型调用）时，都落一条 `agent.action{tool:'system', ok:false}`，summary 写明是哪个上限。

**行事对象与可用工具**：

| 工具 | 为本人 | 为他人 | 说明 |
|---|---|---|---|
| `pass()` | 群聊 | 群聊 | 无声跳过 |
| `knowledge_search(query)` | 全部本人资料与记忆 | 仅 `shared` | 关键词按空白与中文标点切分，`ILIKE` 命中数排序，取前 8 条；结果文本每条为 `标题：正文`，无命中返回 `无结果` |
| `memory_save(title, body)` | ✓（默认 private） | ✗ | 写 notes，authorId=代理 |
| `delegate_to_teammate(handle, task)` | ✓ | ✓（只能交给同组专员，且专员同样处于"为他人"限制） | 同步调用专员一次运行，结果作为工具返回；深度 ≤2 |
| `escalate_to_owner(question)` | —（本人就在） | ✓ | 见 C3 |
| `create_commitment(title, dueAt?)` | ✓ | ✓（处理人=本人，requester=提问者） | 生成 commitment 待办 |
| `negotiate(personHandle, goal)` | ✓（仅 front） | ✗ | 见 C4 |
| `negotiation_reply(status, message, proposal?)` | 仅协商会话中 | — | 见 C4 |
| `device_list/read/write/exec` | ✓（仅绑定了 Runner 的代理） | ✗ | 见 R |

**系统提示**（`prompt.ts`）必须包含：代理身份（"你是{本人}的{代理名}，你是 AI，不是本人"）；`description`；为他人办事时追加 `delegationPolicy` 与三出口规则（能答就答并注明依据；超出授权调用 `escalate_to_owner`；涉及本人设为不可谈的话题直接拒绝）；可用工具说明；"用中文、简洁"。代理发出的消息在界面上一律带"某某的代理"标识，永不冒充本人。

**Mock LLM**（`mock-llm.ts`，e2e 与测试依赖它，必须确定性）：读取本次运行的触发文本（人类消息原文、上报答复原文或协商对方的上一步），按以下优先级：
1. 本次运行中已有工具结果 → 最终文本 `完成：<工具结果前 60 字>`，不再调工具。
2. 触发文本中的指令（第一个命中者生效）：`#pass`、`#delegate:<handle> <task>`、`#escalate <问题>`、`#note <关键词>`、`#remember <标题>|<内容>`、`#commit <标题>`、`#negotiate:<handle> <目标>`、`#ls <路径>`、`#read <路径>`、`#write <路径>|<内容>`、`#exec <命令>` → 调对应工具。
3. 群聊中，文本未 @ 本代理、也不含本代理 handle → `pass`。
4. 上报恢复运行时 → `本人答复：<答复原文>`。
5. 协商中：发起方第一步 `continue` + proposal `{"slot":"周四 15:00"}`；应答方看到 proposal 时，若协商目标含 `#needowner` 则 `need_owner`，含 `#reject` 则 `reject`，否则 `agree` 同一 proposal。
6. 其余 → `收到：<触发文本>`。
Mock 也要产生流式 `draft`（按 8 字切片）和 `llm_requests` 记录（tokens 按字数估算，`provider='mock'`）。

### 核心流程

**注册与代理组**：better-auth 注册 → 调 `/api/onboarding` → 事务内建 member、human principal、两个 agent principal（handle：`<handle>-chief`、`<handle>-ops`；显示名：`<本人>的幕僚长`、`<本人>的执行助理`）及 agents 行。handle 规则 `^[a-z][a-z0-9-]{1,30}$`，租户内唯一，冲突 409。

**C1 和自己的代理组聊**：本人与自己的某个代理开 dm，或建群拉入多个自己的代理。发消息 → 事件落库 → 调度器触发代理 → `draft` 流式 → 回复落库。

**C2 真人互聊**：两人 dm 或多人群聊。没有代理成员的会话，服务端不启动任何代理运行。

**C3 别人找我的代理组**：
1. Bob 在通讯录点 Alice 旁边的"找她的代理" → 建 dm（Bob ↔ Alice 的幕僚长），**同时把 Alice 以 observer 身份加入**（她能看、能以本人身份插话，插话即 `message.posted`，actor=Alice）。
2. 幕僚长以"为他人"身份运行：可检索 Alice 的共享资料、可交给同组专员、可上报。
3. 上报：`escalate_to_owner(question)` → 事务内建 `work_items(kind=decision, ownerId=Alice, requesterId=Bob, conversationId)`、落 `escalation.created` 事件（界面显示"已转给 Alice 本人"）→ 本次运行结束 → Alice 收到 `work_item` 推送。
4. Alice 在"待我处理"里答复（可勾"存为共享资料"→ 写 notes，visibility=shared，authorId=Alice）或拒绝 → work_item 置 done → 落 `escalation.resolved` → 调度器以 Alice 的答复为触发恢复幕僚长运行 → 幕僚长回复 Bob。拒绝时幕僚长告知 Bob 本人暂不答复。
5. Alice 的侧栏有"我的代理在对外"分组，列出她作为 observer 的会话。

**C4 代理之间协商**：
1. Alice 对自己的幕僚长说"和 Bob 约周四讨论预算"→ 幕僚长调用 `negotiate('bob', 目标)`。
2. 服务端建 `conversations(kind=negotiation)`，成员：两个幕僚长（member）、Alice 与 Bob（observer）；`negotiation = { initiatorAgentId, responderAgentId, goal, step: 0, maxSteps: 8, state: 'running'|'waiting_owner'|'ended', lastProposal? }`。在 Alice 原会话落 `agent.action`（"已发起与 Bob 的代理协商"）。
3. 两个幕僚长轮流运行，**每次运行必须以一次 `negotiation_reply` 结束**（不调用则服务端视为 `continue` 且 message 取其文本）；每步落 `negotiation.step`。
4. 判定：对方以 `agree` 回应且 proposal 与上一个 proposal 深度相等 → `agreed`；任一方 `reject` → `rejected`；步数达 8 → `exhausted`；`need_owner` → state=`waiting_owner`，按 C3 第 3–4 步给该代理的本人建 decision 待办，答复后恢复同一代理。
5. 结束时落 `negotiation.ended`；若 `agreed`，给 Alice 和 Bob 各建一条 `confirmation` 待办（带 proposal）；两人都 confirm → 两条都 done，并在协商会话落 `confirmation.resolved` ×2；任一 reject → 另一条也置 cancelled。发起方幕僚长在 Alice 的原会话里回一句结果摘要。

**R 设备 Runner**：
1. Alice 在"设备"页点"添加设备"→ 得到配对码（6 组 4 位，10 分钟一次性，库里只存哈希）。
2. 在她的电脑上：`bun run --cwd apps/runner start pair <配对码> --server http://localhost:8930 --name 我的MacBook` → 调 `/api/runners/pair` → 本地写 `~/.orgos/runner.json`（`{ server, runnerId, token }`，权限 0600；`ORGOS_RUNNER_HOME` 可改目录，测试用）。
3. `bun run --cwd apps/runner start serve --workspace <目录>` → 出站连 `/runner/ws?token=`（ws-bridge 照搬 wisp）→ 发 `hello` 声明四项能力 → 服务端置 online 并推 `runner` 帧。
4. Alice 把"执行助理"绑定到这台设备（PATCH runnerId）。之后执行助理为 Alice 办事时有 `device_*` 工具。
5. `device_list/read` 直接下发；`device_write/exec` 先建 `approval` 待办（显示设备名、能力、完整参数），代理运行挂起等待，最长 10 分钟；approve → 下发执行；deny 或超时 → 工具返回"本人拒绝/超时"。
6. Runner 执行：路径一律 `resolve(workspace, p)` 后校验仍在 workspace 内，否则返回错误；`shell.exec` 用 `Bun.spawn(['/bin/sh','-c',cmd], { cwd: workspace })`，60s 超时杀进程，输出合并截断到 64KB。设备离线 → 工具立即返回"设备离线"。

## 边界情况

| 情况 | 期望行为 |
|---|---|
| 未登录访问 /api 或 /ws | 401 / WS 以 4401 关闭 |
| 访问其他租户的会话、待办、代理、设备 | 404 |
| 非成员读取同租户的会话 | 404 |
| 他人私聊我的专员 | 400 `AGENT_NOT_REACHABLE`（只能找幕僚长） |
| 删除幕僚长 | 403 |
| 消息空或超 8000 字 | 400 |
| 同一对人重复建 dm | 返回已有会话 200 |
| 代理运行中又来人类消息 | 当前步完成后停止，新一轮从新消息开始；不出现两个代理运行同时写同一会话 |
| DeepSeek 超时/5xx/限流 | 重试 2 次（1s、3s）；仍失败落 `agent.action{ok:false}` 与一条"模型暂时不可用"消息；`llm_requests` 记 httpStatus |
| 计量解析失败 | `parseError=true`，tokens 为空，回复照常 |
| 代理之间来回超过 8 次无人介入 | 停止并记录原因 |
| 协商对方代理的本人不在同租户 | `negotiate` 工具返回"找不到此人"，不建会话 |
| 待办重复处理 | 409 |
| 上报后本人长时间不答复 | 待办一直 open；提问方会话保持"已转给本人"状态 |
| 配对码过期或已用 | 400 `PAIRING_CODE_INVALID` |
| Runner token 被吊销 | 立即断开 4003；之后连接 401 |
| Runner 断线重连 | 退避重连后重新 hello；执行中的 job 在服务端 60s 超时后返回失败 |
| 设备路径越界（`../`、绝对路径指向 workspace 外、符号链接逃逸用 realpath 校验） | 返回错误，不读写 |
| 命令输出超 64KB | 截断并在末尾注明"已截断" |
| 同一设备同时收到多个 job | 并行执行，按 jobId 回结果 |
| 代理为他人办事时尝试设备工具或私有资料 | 工具不在可用列表；即便模型编造调用，也返回"无权限" |
| 浏览器 WS 断开重连 | 前端按每个会话已知的最大 seq 调 `events?after=` 补齐 |

## 实施步骤

1. **S1 骨架与数据层**（依赖：无）：workspaces、配置、`scripts/dev-db.sh`（容器 `orgos-postgres`，5470）、全部表的 Drizzle schema 与迁移、better-auth、`scoped()`、`/api/onboarding`、`/api/me`、`/api/directory`、`/healthz`、`scripts/seed.ts`（租户"测试公司"：alice、bob、carol；租户"别家公司"：dave；测试密码写在 seed 文件里并在 README 注明仅限本地）、`decisions/0001-agent-loop.md`。

## 验收标准

机器关（每条独立运行，看真实退出码，不接管道）：

1. `bun install && bash scripts/dev-db.sh && bun run db:migrate` 退出码 0；重复执行 `dev-db.sh` 仍为 0。
2. `bun run typecheck`、`bun run lint`、`bun run test` 各自退出码 0；集成测试连真实 Postgres（`orgos_test`）。
3. `MOCK_LLM=1 bun scripts/e2e.ts` 退出码 0。脚本自起服务端于 8931、自建两个租户与用户、结束后清理，并逐项断言：
	- **C2**：alice 与 bob dm 互发各一条，双方 WS 均收到 `event`；该会话 `llm_requests` 行数为 0。
	- **C1**：alice 对自己的幕僚长发"你好"→ 收到至少一个 `draft` 帧与一条来自幕僚长的 `message.posted`，正文为 `收到：你好`；发 `#delegate:alice-ops 整理周报` → 出现 `agent.action`（tool=delegate_to_teammate）且最终回复以 `完成：` 开头；发 `#remember 私事|下周三请假看牙` 后 notes 表多一行 authorId=幕僚长、visibility=private。
	- **群聊轮次**：alice 建群含幕僚长与执行助理，发 `@alice-ops 你好` → 只有执行助理回复，幕僚长无消息（pass 不落消息）。
	- **C3**：alice 建共享资料"Q4 预算口径：不含税"；bob 找 alice 的代理发 `#note 预算` → 回复以 `完成：` 开头且含"不含税"；bob 再发 `#note 看牙` → 回复含"无结果"且不含"请假"（私有记忆不外泄）；alice 本人对自己的幕僚长发 `#note 看牙` → 回复含"请假"（为本人时可见）；bob 发 `#escalate 交付能否提前到 10 月 1 日` → 出现 `escalation.created`，alice 的 `GET /work-items` 有一条 decision；alice 以"可以"答复并勾选存为资料 → bob 的会话收到 `本人答复：可以`，notes 多一条 shared。alice 能 `GET` 这个会话（observer）。
	- **C4**：alice 对幕僚长发 `#negotiate:bob 约周四讨论预算` → 出现 kind=negotiation 会话，`negotiation.ended.outcome='agreed'`，proposal 为 `{"slot":"周四 15:00"}`；alice 与 bob 各有一条 confirmation 待办；两人 confirm 后两条均为 done。再发一次目标含 `#needowner` 的协商 → bob 收到 decision 待办，答复后协商继续并结束。目标含 `#reject` → outcome=`rejected`，无 confirmation 待办。
	- **R**：用临时目录作 `ORGOS_RUNNER_HOME` 与 workspace，脚本以子进程执行 runner 的 pair 与 serve；alice 把执行助理绑定到该设备，之后以下指令都由 alice 发给自己的执行助理（dm）：`#ls .` 得到目录列表，无待办产生；发 `#exec echo hi` → 产生 approval 待办，approve 后回复含 `hi`；再发 `#exec echo no` 并 deny → 回复含"拒绝"；发 `#read ../../etc/passwd` → 回复含错误提示且未读到内容；吊销设备后 runner 子进程连接被关闭，其重连握手被拒（HTTP 401）；bob 找 alice 的幕僚长发 `#exec echo x` → 回复含"无权限"，且不产生 approval 待办。
	- **租户隔离**：dave 请求 alice 的会话、待办、代理、设备各返回 404；dave 的 `/api/directory` 不含 alice；dave 找 alice 的代理（用 alice 幕僚长 id 建 dm）返回 404。
	- **防循环**：alice 建群含自己的两个代理，发 `@alice-chief @alice-ops 聊聊`（mock 下两者的回复都会复述对方 handle，互相触发）→ 20 秒内停止，代理消息总数 ≤8，最后一个事件是 `agent.action{tool:'system'}` 且 summary 指明上限。
4. `DEEPSEEK_API_KEY=… bun scripts/smoke-llm.ts` 在有网络时退出码 0：真实模型下完成 C1 一轮（回复非空）与 C3 一次上报（模型在被问到明显超出授权的问题时调用了 `escalate_to_owner`，允许重试 3 次取一次成功）；`llm_requests` 中对应行 `costMicroUsd > 0`，且响应中无推理内容（思考已关）。
5. `grep -rn "DEEPSEEK" apps/runner` 无结果（Runner 不接触密钥）。
6. 界面走查（验收方用浏览器执行）：以 alice/bob/carol 三个账号在 `http://localhost:8930` 完成 C1–C4 与 R 各一次，每一步界面上都能看到对应的消息、"已转给本人"、待办、协商步骤与设备审批卡片；代理消息均带"某某的代理/幕僚长"标识。

## 明确禁止

- 不许引入规格外的依赖。允许的运行时依赖仅：hono、drizzle-orm、postgres、better-auth、zod、ky、next、react、react-dom、tailwindcss 及其官方 PostCSS 插件；开发依赖：drizzle-kit、typescript、vitest、@biomejs/biome、@types/*。**不引入 pi、LangChain、任何 agent 框架、任何 UI 组件库以外的状态管理库**；需要 UI 组件时手写或用 shadcn/ui 的生成代码（源码拷入仓库，不算依赖）。
- 不许在 `apps/runner` 出现任何 LLM 调用或密钥。
- 不许写不带租户条件的业务查询；不许更新或删除 `events` 行。
- 不许让代理以本人名义发消息，或在界面上把代理消息样式做成与本人一致。
- 不许为了让测试通过而改弱断言、跳过用例或在生产代码里判断 `NODE_ENV==='test'`；mock 只能经 `MOCK_LLM=1` 切换 LLM 客户端。
- 不许拷贝 wisp 的会话、沙盒、集群、看板、定时、市场代码。
- 界面不用 emoji；不用 `backdrop-filter`（本机 Chromium 下有整块不绘制的已知问题）。
- 交付物不含过程叙事（"此处已修复""v2 改为"之类的注释或文档）。
- 在 git 里：施工者不提交，由验收方验收通过后提交。
