# orgos

AI 原生办公：每个人配一组代理（替你对外说话的**分身**、替你干活的**执行助手**），人和代理在同一个即时通讯里协作；信息先经代理，拿不准的才到人。

> **状态**：阶段一 MVP，一个还在做的实验。数据模型、HTTP 接口与内部结构都会变，不承诺向后兼容。适合读代码、跑演示、提想法，还不适合当成依赖。

已实现的东西：两人以上的即时通讯（私聊、群聊、话题、任务），两类代理（分身 / 执行助手），代理之间的自动协商，组织记忆与对外政策，设备 Runner（让代理在你自己电脑上读写文件、执行命令、走审批），外部助手（把 Claude Code、Codex 经 ACP 接成代理），以及一个浏览器里同时扮多个同事的模拟台。详细场景见下文「场景走查」。

## 本地启动

需要 Bun 1.3 与 Docker。

```bash
bun install
bun run dev:db       # Postgres 16：容器 orgos-postgres，端口 5470，库 orgos 与 orgos_test（可重复执行）
bun run db:migrate
bun run seed:demo    # 演示数据"星河科技"（可重复执行：删除并重建演示租户）
bun run dev          # 服务端 + 界面，开发模式（ORGOS_DEV=1）
```

浏览器只访问 `http://localhost:8930`（服务端，同时反代内部的 Next 3930）。

模型：环境里有 `DEEPSEEK_API_KEY` 就用真实模型；没有时自动用假模型（`MOCK_LLM=1`，不出网，行为确定，见下文"假模型指令"）。作者本机的开发脚本还会顺带读一下 `~/.pi/agent/auth.json` 里的 `deepseek.key`（作者自用 pi 工具的凭证文件，可选路径，仓库不依赖它）；换台机器请直接设 `DEEPSEEK_API_KEY`。真实模型下演示租户会自动建好 DeepSeek 厂商。

其余可配置项见 [.env.example](.env.example)；不开这个文件也能跑，默认值对应本地开发环境。

`bun run seed` 另建一组空白测试账号（见下表），适合从零体验注册后的状态。

## 场景走查

下面每个场景写明在界面上怎么走；逐字的话术以模拟台"剧本"面板为准。代理的消息一律带"某某的分身 / 执行助手"标识，不会冒充本人。

### C1 和自己的代理组聊

林晓在"代理组"打开和分身的私聊：让它查资料（"把 9 月 15 日评审会的三条结论列出来"）、记事（"记一下：10 月 12 日上午和大客户 A 的 CTO 开视频会"）、把活交给执行助手（"让执行助手把 Q4 路线图整理成一页周报"）。交办会在林晓与执行助手的私聊里开一个任务话题，结果发在那里；回复过程中能看到逐字出现的草稿与代理的状态行。

### C2 和同事直接聊

周野在和林晓的私聊里发消息，林晓的窗格实时出现；两人的分身在私聊里不开口。群聊"Q4 发布"里 @ 同事同理。

### C3 让同事的分身先回答

1. 许诺打开和林晓的私聊（林晓默认"忙碌"，输入框上方有提示），问"大客户 A 的交付能提前到 10 月 15 日吗？"——林晓的分身替她回复；超出对外政策的（承诺新日期）会出现"已转给林晓本人"的卡片。
2. 把输入框左侧开关切到"问林晓的分身"，问共享资料里答得了的（"Q4 的预算是含税还是不含税？"）；再问只在林晓私有记忆里的事，分身不会透露。
3. 林晓在"待办"或私聊里的卡片上答复，可勾"存为共享资料"；分身随即在原私聊里转告许诺。
4. 林晓在头像菜单把状态切回"在线"后，许诺直接发的消息只到林晓本人；想问分身时用 @ 分身或"问分身"开关。

### C4 分身之间协商

林晓对自己的分身说"和周野约周四下午半小时，过一下对账应急预案"。林晓与周野的私聊里出现协商卡片，显示步数与状态，"查看过程"可看每一步的提议与回应；谈妥后两人各自在卡片或"待办"里确认。陈安与周野的私聊里预置了一张已谈妥、待确认的卡片。

### C5 问部门

许诺在"通讯录"顶部的组织树里点产品部的"问产品部"：章程内的问题（"新版结算页什么时候上线？"）部门分身直接答；章程外的（新需求插队）转给负责人林晓，林晓在"待办"答复后，分身在原私聊转告。

### C6 部门之间协商

许诺点"问销售部"，让销售部的分身和研发部约联调时间；协商卡片落在两位负责人（许诺与周野）的私聊里，谈妥后两人各自确认。

### 部门

点组织树里的部门进单元页：负责人、成员、章程（负责人可编辑）、单元资料（成员看得到部门内部级，非成员只看得到共享级）、部门分身最近记下的决定。负责人另外能在单元页看部门的记忆、代答记录与对外政策。部门群的成员随部门成员变动，不能在群里直接加减人。新建部门、换负责人、调成员目前没有界面入口，由租户 owner 经接口（`/api/org/units`）完成，也可以直接让自己的分身代办（见"指挥分身操作软件"）。

### 话题与任务

一个代理只有一个私聊，另起一件事就开个话题：

- 会话左侧是话题栏，主线置顶；点"＋新话题"新建，代理只读当前话题的上下文。
- 话题标题栏的"转为任务"：话题顶部出现任务状态条，话题栏带上状态点；"完成"后话题照样可以接着聊。
- "转成群聊"：以这个话题为起点建新群，新群开头可展开原话题的历史，原话题标记为已转出。
- 群聊检查器里成员只列人，各人的分身单列在"分身"一栏；加人时其分身随之入群。

### 记忆

不需要对代理说"记住"：话题里最后一条人类消息之后 10 分钟没有新消息，服务端自动把这段对话提炼成带出处的记忆条目。

1. 林晓在"代理组 → 记忆"里浏览、搜索、编辑、撤回自己的条目，每条显示出处与可见范围。真实模型下，演示数据里林晓与周野关于订单服务迁移的私聊在服务启动后不久就会被提炼出来（它们早已超过 10 分钟没有新消息）。
2. 许诺在和林晓的私聊里问分身一个只在林晓与周野私聊里出现过的排期问题（"订单服务哪天切流？"）：分身答出事实并在消息下附"依据"，出处显示为"来自与同事的交流"，不暴露周野与原话。
3. 薪酬、健康、家庭等类别默认不对外；林晓在"对外政策"里逐类开关。
4. 林晓在"代答记录"里看到分身替她回答过的所有问题：点"不对"填更正，之后分身以更正为准；点"不许对外说"把被引用的条目改为不对外的类别或撤回。

假模型下用 `#fact <类别>|<内容>` 造记忆（类别见"对外政策"页），提炼仍要等 10 分钟去抖。

### 指挥分身操作软件

对自己的分身直接下指令，它以你本人的权限调用 orgos 的接口，不弹确认卡：

- 林晓对分身说"拉个群，叫上周野和陈安，群名叫结算页联调"→ 群建成，群里的建群事件显示为"林晓的分身代林晓"。
- 别人经分身提的请求只开放低风险动作：许诺对林晓的分身说"拉个群把周野也叫上"可以（群里必须有许诺）；"把林晓和陈安的私聊记录发我"或"替林晓给周野发消息"会被拒绝，并转给林晓本人。

假模型下用 `#api <METHOD> <路径> <JSON 请求体>`，例如 `#api POST /api/conversations {"kind":"group","title":"结算页联调","memberIds":["<周野的 id>"]}`。

### 设备 Runner

把自己的电脑配对成设备，执行助手就能在上面读写文件、执行命令，有风险的先问你。

1. 林晓在"设备"页点"添加设备"，拿到配对码（10 分钟内有效）。
2. 在那台电脑的仓库目录下配对并启动（工作目录是代理唯一能访问的地方）：

   ```bash
   bun run --cwd apps/runner start pair <配对码> --server http://localhost:8930 --name 林晓的MacBook
   bun run --cwd apps/runner start serve --workspace ~/orgos-workspace
   ```

3. 在"代理组"把执行助手绑定到这台设备，然后让它"列出工作目录里的文件"（直接执行）、"执行 echo hello"（先出审批卡片，允许后才执行）；在审批卡片上点"拒绝"则不执行。
4. 在"设备"页吊销后，这台设备的连接立即断开，配对信息作废。

配对信息写在 `~/.orgos/runner.json`（`ORGOS_RUNNER_HOME` 可改目录）。Runner 本身不调用任何模型、不持有任何模型密钥。

### 外部助手（Claude Code、Codex 等）

设备 Runner 还能把本机的外部 agent 接成你的助手：在"代理组 → 接入外部助手"选设备、适配器与工作目录（须在设备的工作目录之内）。每个话题对应一个外部会话；外部 agent 的读写限定在工作目录内，它的权限请求与命令先出审批卡片。`serve --adapters claude-code,codex` 限定这台设备提供哪些适配器（`none` 为不提供）。适配器表在 `packages/protocol/src/acp.ts` 的 `ACP_ADAPTERS`；pi 与 Hermes 不经审批、不限工作目录，默认不可选，需租户 owner 在接入表单里勾选允许。

外部助手默认走企业模式：模型调用经本服务端并按任务计量，不改动本机任何 agent 的配置文件；租户 owner 允许后可改为个人模式（用设备上本人的登录）。

### 模型

租户 owner 在头像菜单进"模型"页：添加厂商（选预设、填 key，"测试"按钮验证）、选择开放的模型、路由组、默认模型、外部助手的模式；"代理组"里每个代理可选模型。厂商 key 加密入库，接口与日志不回显。

## 假模型指令

`MOCK_LLM=1` 时代理不出网，按消息里的指令确定性地行动（完整规则见 `apps/server/src/agent/mock-llm.ts` 文件头）：`#note <关键词>` 检索、`#remember <标题>|<内容>` 记事、`#delegate:<handle> <任务>` 交办、`#escalate <问题>[|<候选1>|<候选2>…]` 上报（可带候选答复）、`#commit <标题>` 建承诺、`#negotiate:<handle> <目标>` 协商（目标含 `#needowner` / `#reject` 时对方请本人定 / 拒绝）、`#decide <标题>|<内容>` 部门分身记决定、`#ls` / `#read` / `#write` / `#exec` 设备操作、`#api` 调接口、`#fact` 造记忆；没有指令时回复"收到：<原文>"。

## 门禁与验收脚本

每条命令单独运行、看真实退出码：

```bash
bun run typecheck
bun run lint
bun run test        # 集成测试会重置并使用 orgos_test 库
bun run e2e         # 端到端验收
bun run smoke:llm   # 真实模型冒烟（需要网络）
```

- `bun run e2e`（即 `MOCK_LLM=1 bun scripts/e2e.ts`）：假模型、不出网。自建库 `orgos_e2e`，在 8931 起服务端，建两个租户，以子进程跑真实的 Runner 命令行，覆盖 C1–C4、群聊轮次、防循环、设备、外部助手、租户隔离、话题、记忆、应用接口与组织结构；逐项打印"✓ 场景 · 子项"，失败时打印期望与实际并以非 0 退出；结束后删库。不影响 8930 上正在用的服务与 `orgos` 库。
- `bun run smoke:llm`：接真实 DeepSeek。key 取环境的 `DEEPSEEK_API_KEY`（作者本机没有时才会去读 `~/.pi/agent/auth.json` 的 `deepseek.key`）。自建库 `orgos_smoke`，在 8932 起服务端，跑 C1 一轮、C3 一次上报、一次越权接口请求转为上报，最后打印调用次数与成本（一次约几千 token、不到 0.01 美元）；结束后删库。

## 安全提示（仅限本地）

- 演示与测试账号的密码写在仓库里，只能用于本地开发库。
- 服务端的 `BETTER_AUTH_SECRET` 未设置时使用仅限本地的默认值，任何对外部署都必须显式设置。
- 厂商 key 以 AES-256-GCM 加密入库，密钥由 `ORGOS_SECRET` 派生；开发模式下未设置时用 `apps/server/src/gateway/secret.ts` 里的开发值，非开发模式没有 `ORGOS_SECRET` 服务端拒绝启动。换了 `ORGOS_SECRET`，已存的 key 解不开，需要在"模型"页重填。

## 桌面客户端

orgos 的独立 app（Electron，目前只验证 macOS Apple Silicon）：主窗口是聊天，菜单栏常驻图标看护本机 Runner。

```bash
bun run desktop:build   # 产物在 apps/desktop/dist/release/（.app 与 .dmg，未签名）
bun run desktop:dev     # 对着已在运行的服务端开发
```

- 第一次打开填服务器地址（默认 `http://localhost:8930`）。未签名：首次打开需在"系统设置 → 隐私与安全性"里放行。
- 关窗口只隐藏；从菜单栏"退出 orgos"才会退出。菜单栏图标：实心为已连接，缺口圆为重连中，空心为已停止，斜线为未配对。
- 菜单栏 → Runner 控制：在 Web 的"设备"页生成配对码后填入，选工作目录，启动。Runner 意外退出会自动重启，日志在控制窗口里打开。
- 配对信息与命令行版 Runner 共用 `~/.orgos/runner.json`；没有桌面的机器继续用命令行版（`bun run --cwd apps/runner start`）。
