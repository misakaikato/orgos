# 0002 任务是一等工作对象；组织单元是主体

- 日期：2026-09-27
- 状态：已采纳（用户确认：外部 agent 会话映射为"任务"并对齐 A2A；组织单元的代理叫"<部门名>的分身"；两项都进入阶段一）

## 任务

外部 agent（Claude Code、Codex 等）的一次会话，以及我们自己的代理之间的一次交办，统一建模为**任务**：交给某个执行者、有边界的一件事，带状态、产出、过程记录与花费。

- 不映射为"会话"：会话是人与人、人与代理之间长期存在的关系空间；外部会话是一次性的、数量多、上下文会被压缩，映射成会话会让列表爆炸。
- 不映射为"消息"：太细，状态、审批、产出没有归宿。
- 状态机照抄 A2A 的任务定义（submitted / working / input_required / awaiting_approval / completed / failed / canceled），将来对外暴露 A2A 时不需要翻译。
- 一个任务对应一个外部会话；同一任务内追问 = 继续同一外部会话；新交办 = 新任务。
- 外部 agent 经设备 Runner 以 ACP（Agent Client Protocol，stdio 上的 JSON-RPC）接入；Runner 端的 ACP 客户端从 wisp `runner/src/acp/` 移植，沿用其"子进程看不到任何 orgos 凭据"的铁律。外部 agent 使用设备主人自己的订阅或 key，orgos 不代付、不代管。
- 聊天里只放任务卡片；完整过程进 `task_logs`（只追加），不进会话事件流。
- 外部 agent 的权限请求映射为我们的审批待办。

## 组织单元

组织单元与人、代理并列，是一种**主体**（`principals.kind = 'unit'`）。

- 代理的所属者从"必然是人"放宽为"人或组织单元"。组织单元的分身（`<部门名>的分身`）就是归属于该单元的 front 代理，归属、授权、上报、协商机制原样复用。
- 组织分身上报的"本人"是单元负责人。
- 硬边界：组织分身只记录单元层面的产出（决定、承诺、共享资料），不读成员的私聊与私有资料，不产出个人行为统计。
