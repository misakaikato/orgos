# 0001 阶段一代理循环自写，不用 pi

- 日期：2026-09-26
- 状态：已采纳
- 适用范围：`apps/server/src/agent/`（阶段一）

## 背景

阶段一需要一个代理运行循环：组装提示 → 调模型 → 执行工具 → 继续，直到无工具调用后落一条消息。候选有两个：自己写一个最小循环（规格目标 ≤300 行），或复用 wisp 用过的 pi 系列包（`@earendil-works/pi-*` 0.82.1）。

## 决定

阶段一自己写循环，不引入 pi 或任何 agent 框架。

## 理由

1. **只接 DeepSeek，且要带厂商参数。** 阶段一唯一的供应商是 DeepSeek，请求必须带 `thinking: { type: "disabled" }`（不带时思考会吃光 `max_tokens`），并且要 `stream_options.include_usage` 以便逐次记账到 `llm_requests`。自写循环对请求体有完全控制，不必去确认框架是否透传这类非标准参数。
2. **测试依赖确定性 mock。** e2e 与集成测试都靠 `MOCK_LLM=1` 下的确定性假模型（按触发文本里的指令调工具、按 8 字切片产生流式草稿、按字数估算 tokens）。在自写循环里，mock 就是换掉 LLM 客户端这一层；套在框架上则要额外弄清框架的供应商抽象怎样注入假实现。
3. **pi 的相关层未经验证。** `pi-agent-core` 0.82.1 虽然导出了 `Agent`、`agentLoop` 与 `beforeToolCall` 钩子，看起来够用；但 wisp 的 Runner 走的是 `pi-coding-agent` 的会话层，从未直接在 `pi-agent-core` 这一层使用过它。本项目需要的"为本人 / 为他人"工具收窄、审批挂起最长 10 分钟、人类新消息到来时停在当前一步，都要落在工具调用前后的钩子上，而这些钩子在我们手里没有任何使用经验。
4. **规模小。** 需求是单一供应商、固定工具表、最多 8 次模型调用的循环，自写的成本低于评估和适配一个框架的成本。规格也明确禁止引入 agent 框架。

## 何时重新评估

接入第二个模型供应商时重新评估：届时"多供应商适配"成为主要工作量，框架的价值才会超过它带来的不确定性。评估时先在 `pi-agent-core` 这一层做一个带 `beforeToolCall` 审批挂起与中止的最小原型，再决定是否迁移。
