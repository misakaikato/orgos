# 0004 会话内话题；每次代理运行都有运行记录

- 日期：2026-09-28
- 状态：已采纳（用户在五套方案中选定 B）

## 问题

主流 agent 工具一个 agent 有多个会话；若把每个会话映射成 IM 里的一个聊天，一个代理就会在列表里出现多个私聊，违反 IM 心智。

## 决定

- 每个会话（私聊、群聊）内部分为多个**话题**；每个会话有一个默认话题"主线"。话题是上下文的边界：代理只读当前话题的历史；外部 agent 每个话题对应一个 ACP 会话。
- 每个代理与本人恰好一个私聊；要另开一条线就在私聊里"＋新话题"。
- **任务 = 带状态的话题**（kind=task，关联 tasks 行）。对话型与任务型因此是同一种东西：普通话题可"转为任务"，任务完成后仍是一个可继续聊的话题。
- 话题可"转成群聊"：带着该话题的历史开一个新群，拉人加入。
- 每一次代理运行写一条运行记录（runs），审批、过程、计量、打断、记忆取材都以它为单位；任务的过程记录即其运行记录的集合。
- 长话题靠压缩续命（结构化检查点：目标、进展、决定、下一步、涉及文件），最近约 2 万 token 保留原文；每轮附"近期工作简报"：该代理过去两天在其他话题与会话里的最后一句（≤10 行），放在历史之后而非系统提示中，以保住提示缓存。压缩前的"记忆冲刷"在记忆层一步实现。
- 群聊：拉某人进群时其分身自动入群、退群时一起退；群成员列表只列人。
- pi 与 Hermes 适配器不经 orgos 审批、不限工作目录：保留，但默认不可选，需租户 owner 开启，创建时本人勾选确认。

## 被放弃的方案

A 房间制（Lorca：另开一条线就建群）列表易膨胀；C 代理下挂会话违反 IM 习惯；D 任务为中心让闲聊也得建任务；E 自动分段不可控。
